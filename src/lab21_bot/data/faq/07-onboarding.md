# Заявки и онбординг

Вступление в Lab21 идёт через заявку в боте. Staff обрабатывает её в разделе **Комьюнити → Заявки**.

## Виды заявок

| Вид | Кто подаёт | Что заполняет |
|-----|------------|---------------|
| Сообщество (`community`) | будущий участник | био + навыки свободным текстом |
| Сотрудник (`staff`) | кандидат в staff | без навыков; роль выбирает утверждающий |

Участник **не выбирает** навыки из каталога: пишет теги своими словами. Модератор в **Комьюнити → Заявки** сопоставляет их с системным списком при одобрении.

## Статусы

| Статус | Значение |
|--------|----------|
| `pending` | очередь на одобрение (обычный путь для новых заявок сообщества) |
| `skill_validation` | наследие / особый случай, когда в заявке уже проставлены каталожные навыки с проверкой |
| `approved` | принят в систему |
| `rejected` | отклонён (с заметкой или автотекстом) |
| `expired` | срок ожидания истёк без решения |

## Срок жизни

По умолчанию `application_expire_days = 7` (конец дня через N суток). Планировщик раз в сутки помечает просроченные как `expired` и пишет заявителю и в staff-чат.

## Решение staff

- **Одобрить сообщество** — отметить подходящие навыки из каталога, затем принять. Навыки без валидации выдаются сразу; навыки с `requires_validation` уходят в очередь «На валидации навыков». Также начисляется базовая благодать ранга и ставится `is_approved`.
- **Одобрить валидацию навыков** — навыки из заявки добавляются участнику (после фактической проверки).
- **Отклонить** — статус `rejected`; для валидации навыков без заметки подставляется текст по навыку.
- **Одобрить staff** — обязателен выбор роли; баланс/респект обнуляются, роль назначается.
- **Отклонить валидацию** без заметки — автотекст вида «Не прошел валидацию навыка …».
- События попадают в **журнал** дашборда.

После одобрения staff-заявки бот шлёт **одноразовый инвайт** в служебный чат (бот не может добавить человека сам).
