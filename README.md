# Telegram-бот Lab21

Асинхронный бот для редакции Telegram-канала, внутренней экономики и сбора
контента сообщества Lab21. Все тексты обрабатываются локальной LLM: заметки,
истории и Telegram `file_id` не отправляются в облачные AI API.

## Возможности

- черновики постов из коротких инженерных заметок;
- согласование, редактирование и публикация в основном канале;
- личные интервью сотрудников и напоминания после периода тишины;
- модерируемые истории, мемы, фото, видео и альбомы с обязательным авторством;
- роли сотрудников `Магистр`, `Техножрец`, `Смотрящий`;
- ранги сообщества `Послушник` и `Адепт`;
- неизменяемый журнал лабкоинов, административные проводки и переводы Адептов;
- ранговая витрина, резерв средств, подтверждение и возврат заказов;
- модерируемое посвящение в Адепты как специальная награда;
- перезагрузка из админки с проверкой и установкой обновлений с GitHub.

## Стек и архитектура

- Python 3.12, aiogram 3 и long polling;
- PostgreSQL, async SQLAlchemy и Alembic;
- Ollama (`qwen3:4b` по умолчанию) либо OpenAI-совместимый локальный vLLM;
- APScheduler с часовым поясом `Europe/Moscow`;
- Docker Compose без привязки к конкретному NAS.

На UGREEN DXP480T Plus с 8 ГБ RAM рекомендуется `qwen3:4b`. После расширения
до 16 ГБ можно переключить `LLM_MODEL` на `qwen3:8b`. Ollama работает без
дискретной GPU, но генерация на CPU не будет мгновенной.

## Подготовка Telegram

1. Создайте бота через BotFather и сохраните токен.
2. Добавьте бота администратором основного канала с правом публикации.
3. Добавьте его в служебный чат. Флудилка может быть отдельным чатом: её
   сообщения никогда не считаются активностью канала.
4. Каждый сотрудник должен открыть личный диалог с ботом и нажать `/start`.
   Telegram не позволяет боту первым начать личную переписку.
5. Узнайте числовые Telegram ID владельца, канала и чатов и внесите их в `.env`.
   ID каналов и супергрупп обычно начинаются с `-100`.

Первый пользователь из `BOOTSTRAP_MAGISTER_ID` получает роль Магистра при
каждом старте. Это предотвращает случайную потерю административного доступа.

## Запуск в Docker

```bash
cp .env.example .env
# заполните токен, ID и случайный пароль PostgreSQL
docker compose --profile llm up -d --build
```

Профиль `llm` запускает Ollama и однократно загружает модель из `LLM_MODEL`.
Загрузка `qwen3:4b` занимает несколько гигабайт. Проверка:

```bash
docker compose ps
docker compose logs -f bot
```

Если Ollama уже работает на другом узле, не включайте профиль `llm`, укажите
доступный для контейнера `LLM_BASE_URL` и запустите:

```bash
docker compose up -d --build
```

Для vLLM установите `LLM_PROVIDER=openai`, `LLM_BASE_URL` до локального сервера
и имя модели. Ключ необязателен; если сервер его требует, задайте
`LLM_API_KEY`.

Миграции применяются автоматически перед запуском бота. Данные PostgreSQL и
модели Ollama находятся в именованных Docker volumes.

Сервис `watchdog` слушает запросы на перезагрузку, сверяет ветку GitHub,
собирает новый образ бота и перезапускает его. Ему нужен доступ к
`/var/run/docker.sock`. Для приватного репозитория задайте `GITHUB_TOKEN`.

## Перезагрузка и автообновление

Только Магистр:

- `/update_status` — проверить, есть ли коммиты новее текущей сборки;
- `/reboot` или кнопка «Перезагрузка» в служебном меню — подтвердить рестарт.

При подтверждении бот пишет сигнал в общий volume. Watchdog:

1. клонирует или обновляет репозиторий из `REPO_URL` / `GITHUB_BRANCH`;
2. пересобирает сервис `bot` с актуальным `GIT_SHA`;
3. перезапускает контейнер;
4. оставляет отчёт, который бот пришлёт Магистру после старта.

Локальные незакоммиченные правки watchdog не подхватит: в прод уходит только
то, что уже есть на GitHub.

## Управление

Основное меню открывается через `/start` или `/menu`.

Команды участников:

- `/balance` — ранг и баланс;
- `/history` — последние проводки;
- `/shop` — доступные для ранга награды;
- `/transfer TELEGRAM_ID СУММА ПРИЧИНА` — перевод между Адептами.

Служебные команды:

- `/post` — создать LLM-черновик;
- `/grant TELEGRAM_ID СУММА ПРИЧИНА` — начислить лабкоины;
- `/withdraw TELEGRAM_ID СУММА ПРИЧИНА` — списать лабкоины;
- `/staff TELEGRAM_ID magister|tech_priest|watcher|none` — изменить роль;
- `/reboot` — перезагрузить бота и установить обновления с GitHub;
- `/update_status` — проверить обновления без перезагрузки;
- `/product название | описание | цена | остаток/inf | novice/adept | physical/service/rank | выдаваемый_ранг`;
- `/product_edit ID name|description|price|stock|visible|min_rank ЗНАЧЕНИЕ`;
- `/setting content_silence_days|reminder_hour|transfer_daily_limit ЗНАЧЕНИЕ`.

Пример награды для посвящения:

```text
/product Стать Адептом | Подтверждение вклада в лабораторию | 1 | inf | novice | rank | adept
```

Права:

| Роль | Возможности |
| --- | --- |
| Магистр | все настройки, сотрудники, витрина, экономика и модерация |
| Техножрец | черновики постов и операции с лабкоинами |
| Смотрящий | черновики, модерация материалов и выдача заказов |

Служебная роль и ранг сообщества независимы. Передавать лабкоины могут только
два участника с рангом Адепта. Дневной лимит `0` отключает ограничение.

## Конфиденциальность и эксплуатация

- не коммитьте `.env`;
- ограничьте сетевой доступ к PostgreSQL и Ollama;
- регулярно резервируйте volume `postgres_data`;
- пользовательские медиа не скачиваются на сервер: в БД хранится только
  Telegram `file_id`;
- исправление экономики выполняется новой компенсирующей проводкой, старые
  проводки не редактируются;
- публикация всегда требует явного действия сотрудника.
